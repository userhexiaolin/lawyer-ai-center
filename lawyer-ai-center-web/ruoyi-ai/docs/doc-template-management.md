# 模板上传与文书类型维护

## 上传模板

在管理端「模板管理 → 模板管理」点击独立的「上传模板」按钮，打开上传弹窗；该按钮与手工填写正文的「新增模板」并列。

- 支持 `.docx`、`.doc`、`.rtf`、`.odt`、含可复制文字的 `.pdf`、`.txt`、`.md`；文件不超过 10MB，PDF 不超过 100 页，解析后的正文不超过 40000 字。
- TXT / Markdown 支持 UTF-8（含 BOM）和 GB18030 中文编码。
- 上传弹窗按顺序展示模板名称、模板类型、排序号、启用/停用状态、备注和模板文件。
- 文件解析后，“允许填写的段落”默认全选，提供“全选”按钮恢复全部选择。需要保持原文的标题、条款或署名可以手工取消勾选；更换文件后按新文件的全部段落重新默认选中。
- 点击文件区打开系统文件选择框，或将单个文件拖入弹窗，自动上传并解析正文。模板名称默认取文件名（去掉扩展名），可手动修改；更换文件不会覆盖手动修改的名称。
- 排序号支持手动输入，备注选填。点击「确定」才会按当前填写的名称、类型、排序、状态和备注保存模板，并刷新列表；取消弹窗不会创建模板记录。
- 文件解析失败时禁止确认，重新选择文件即可重试；解析过程中取消或重开弹窗，迟到的结果不会回填到新的表单。
- 上传保存原文件和不可变版本；DOCX 直接用于填写和导出，其他格式先转换并在管理端确认预览版式。扫描版 PDF 需先转为可编辑文字。
- 上传入口和最终创建使用现有模板新增权限。模板上传完成后，可通过列表的「编辑」修改模板正文。

## 菜单与类型维护

管理端新增一级目录「模板管理」，包含两个子菜单：

- 「模板类型」：新增、编辑、排序、启用、停用和删除类型。
- 「模板管理」：现有模板列表、上传、编辑和启停功能。

类型保存在 `legal_doc_template_type` 表中，按当前租户隔离。原有六种类型（民事起诉状、民事答辩状、律师函、合同文书、法律意见书、自由描述文书）初始化为内置类型；新租户首次访问时自动初始化。

用户端 `GET /legal/doc-template/types` 仅返回启用类型；管理端 `GET /legal/doc-template-type/options` 包含停用类型，便于筛选、查看和编辑历史模板。新增模板、上传和起草时会校验类型是否启用；已有停用类型下的模板仍可查看、修改或停用。

## 以后增加类型

在「模板管理 → 模板类型」点击「新增类型」，填写名称、排序和状态后保存。启用后即可在上传模板时选择，用户端刷新文书起草页面后也会出现，无需修改代码或重新发布。新增类型使用通用起草要素；如需专用字段或输出格式，需要另行开发对应起草流程。

自定义类型改名会在同一事务中同步更新当前租户的模板归类。类型下存在任何模板（包括停用模板）时禁止删除；先调整或删除关联模板后再删除类型。

内置类型名称关联现有专用起草流程，不允许改名或删除，可调整排序、状态和备注。`DocumentType.java` 仅作为六种内置类型的初始化数据，不再限制可用类型。

## 起草结果与模板适配

- 上传、启用和使用模板时检查正文标题与所选类型。例如正文为「律师函」的文件不能作为「民事起诉状」使用。历史已存在的错误分类模板会在用户端标明不匹配并禁止选用，不自动改动管理员上传的数据。
- 用户端可选择「标准起草（不使用上传模板）」。没有匹配模板时使用标准起草；有匹配模板时默认选择排序最小的启用模板。
- 民事起诉状和答辩状只以本次填写的起草要素作为案件事实。服务端先将常见模板字段填入已提供内容，再交给模型整理；新的起草请求不混入旧案会话内容。
- 文书起草使用专门的正文输出要求，不套用普通聊天的引用 JSON 输出规则。完成后剥离已识别的法条/案例引用元数据（单个对象或数组），让展示和聊天历史保存同一份结果。诉讼起草另检查核心章节和已知字段。模板填写协议与其他 JSON 业务内容不会被当作引用元数据删除。
- 对已知的未提供程序经过或动机（如多次催讨、资金周转等），按本次事实恢复该章节；不自动加入未提出的费用、利息等请求，并补回遗漏的已填证据。这些检查不能替代律师对完整事实、诉求和法律适用的核对。
- 使用原文件模板时只填写原有空白或占位符，任何勾选均不授权改写模板固定原文；未提供资料保留原字段，不添加待补充说明。结构化模板草稿允许保留原有未填占位符；标准起草产生的意外占位符仍禁止交付。

## 发布与回滚

### 原始模板与多格式下载

执行增量脚本 `docs/script/sql/update/2026-10-20-template-files.sql`，增加私有的 `legal_doc_template_file` 原文件/不可变版本表，不覆盖旧模板及草稿。上传文件只创建待确认版本，确认时绑定模板与允许填写的段落。需要勾选填写区域、查看PDF版式并确认格式后保存。支持DOCX、DOC、RTF、ODT、文字PDF、TXT和Markdown；非DOCX的转换版式以管理端确认的预览为准。扫描件需要先转换成可编辑文字。

Word导出直接填写原DOCX包内的文字节点，保留段落属性、各文字片段的字体属性、表格、图片、页眉页脚、关系和页面设置。占位符以外的固定前后文字不能改写；模板版本一经绑定不再改动，替换文件创建新版本，旧草稿继续使用旧版本。需要同一段多个不同字体的字段时，使用明确的占位符并保留固定分隔文字。仅填写原模板留白或占位符，填入内容增长可能造成自动分页，不改写整段固定内容。

起草助手只生成填写区域的结构化内容；服务器补回固定段落，保存正文和模板版本。页面支持按区域编辑、PDF版式预览以及Word（DOCX）、PDF、Markdown和TXT下载，四种格式均使用同一份当前定稿，导出不调用模型。MD/TXT只承载文字结构，不承载Word字号和分页。模板选项通过 `preservesLayout` 标明是否保存原文件。仅保存正文的历史模板会提示缺少原格式；现有稿件可明确选择“按标准版式下载当前正文”，无需重新生成。要沿用原模板版式，需要在模板管理中补传一次原始 Word，再使用该版本起草；合同无需为此重新上传。标准版式导出通过 `layout=standard` 显式请求，默认仍按原模板导出，不静默降级；结构化草稿即使采用标准版式也校验会话绑定的模板版本和固定段落。

PDF 由填好内容的同一份 DOCX 转换，沿用该 DOCX 的字体、字号、段落、表格、页眉页脚及页面设置。服务器必须安装模板使用的字体，否则转换器可能替换字体；正文增长也可能造成换行、分页变化，正式交付前应查看 PDF 版式预览。

PDF及跨格式转换使用本地LibreOffice。配置 `legal.documents.soffice` 为可执行文件绝对路径；支持系统常见安装位置，或执行 `scripts/deploy/Install-DocumentConverter.ps1` 将已校验的运行时解包到项目 `data/document-converter/runtime/program/soffice.exe`。应用从当前目录的上级目录逐层寻找此运行时。转换进程与配置归当前应用独占，使用随机命名的本地管道，不监听外部网络端口；启动后后台预热，请求串行转换，文件各自隔离。首次初始化最长等待600秒。PDF完整结束标记和PDFBox解析、DOCX中央目录及正文条目均验证通过后立即返回，不等待客户端额外的退出延迟。应用关闭时清理自有进程和临时配置。部署时同时携带运行时或安装系统LibreOffice，并安装模板所需字体。未配置/转换失败时返回明确错误，不返回伪PDF或悄悄套用另一套版式。

模板原文件上限10MB，数据库需允许至少32MB的`max_allowed_packet`。未确认上传版本保留在文件表，可由运维按保留期清理`template_id IS NULL`的记录；已绑定版本不得随模板替换删除，以免破坏历史草稿。

先执行 `docs/script/sql/update/2026-10-20-template-management.sql`，再发布本次后端、管理端和用户端代码。迁移可重复执行，保留已有模板、菜单ID及模板页面原URL，新增类型表并重组菜单。角色与租户套餐按原模板列表、新增、修改、删除权限对应继承类型管理权限；发布后同步租户套餐并重新登录，以刷新菜单和权限缓存。

回滚使用配套的 `2026-10-20-template-management-rollback.sql`，同时恢复匹配版本的前后端。回滚保留类型表和业务数据，以及迁移备份表。
