## 数据库设计与实际结果

没有直接拼接旧数据库导出。将历史 SQL 分离为纯结构基线与审核过的基础数据，再按依赖顺序嵌入当前迁移，产物不依赖外部 `SOURCE` 文件。旧导出中包含的会话、个人联系方式、测试账户、上传文件和存储配置等不进入公开初始化数据。

- 全量文件创建 `ruoyi-ai-lawyer` **123 张表**与 `snail_job` **23 张表**；包括迁移备份/辅助表，不将这些数量解释为业务功能数量。
- 覆盖代码中扫描到的 **72 个显式 `@TableName` 表名**。此项验证表名存在，不等于证明所有 SQL 使用点、所有继承字段或业务行为均正确。
- 明确嵌入 **39 份迁移**，历史 **9 份变更**由基线表示，**8 份回滚 SQL**明确排除。可选外部付费视频模型样例不纳入安装数据，原因记入 manifest。
- 新增[补表迁移](../../ruoyi-ai/docs/script/sql/update/2026-10-30-open-source-missing-tables.sql)，按当前实体补齐旧导出缺少的 `adi_user`、`chat_config`、`knowledge_graph_instance` 与 `knowledge_graph_segment`，不添加运行数据或改变服务端权限代码。
- 公开原版 `admin` 锁定且不含密码；安装者在本机设置自己的 BCrypt 散列，生成一份私有完整 SQL 后只执行该文件。模型、厂商、四个法律助手、自助注册和计费方案均保持停用，调度不预置账户/令牌/任务。
- 全量入口和独立调度入口移除删库/删表行为；数据库重名时应在第一处错误停止。DDL 仍存在部分提交边界，恢复方式在 SQL 说明中明确。
