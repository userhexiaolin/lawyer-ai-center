# 与律行 · Codex 项目长期指令

> 本文件是本仓库的长期约束入口，适用于后续所有相关前端开发与评审。前端规范版本为 V2.0。新增规则必须增量合并，不得覆盖既有架构、运行、安全、权限与测试规则。

## 本仓库的适用机制

- 适用于 `ruoyi-web/` 用户端，以及 `ruoyi-admin/apps/web-antd/`、其依赖的共享组件、主题与前端工程配置；其他新增前端模块同样适用。纯后端工作不必执行前端设计流程。
- 前端任务先阅读 [项目适配与冲突处理](docs/frontend/00-PROJECT-ADAPTER.md)，再按下文读取相关规范。所有路径均相对真实仓库根目录，不能相对子项目或 Skill 目录推断。
- 保留 `ruoyi-web/CLAUDE.md` 的 pnpm、锁文件与编码约定；涉及 O001 时同时遵守 `docs/product/o001/` 的现有 PRD、交互蓝图、`contracts.md` 和 `implementation-decisions.md`，区分已实现能力与规划契约。
- 根规则长期适用，不依赖用户每次显式点名 Skill。发现下级 `AGENTS.md` / `AGENTS.override.md` 时先检查其范围；出现规则冲突须说明并保留更严格的既有业务、安全、权限约束，不得静默覆盖。

## 项目原则

- 与律行是律师业务生产力产品，不是普通 CRUD 后台或 AI 聊天演示。优先保障可追溯、可复核、任务连续性、信息密度、操作效率和安全边界。
- 执行用户给定的功能范围；不得以视觉改造为由删减、虚构或重写既有业务。不得把调研假设表述为已证实需求。
- 先检查仓库已有技术栈、布局、路由、组件、主题、测试、权限和适用的下级 AGENTS.md，再确定修改方式。复用既有设计与业务基础设施；未经批准不得整体替换组件库或另造平行框架。

## 前端开发的强制入口

凡新建或修改前端页面、组件、样式、交互、表单、可视化、图表、响应式布局、空态/错误态、业务入口，统一执行 V2.0。目标依次为事实 / 来源正确与安全、任务可完成与可恢复、操作效率、信息层级和视觉一致性。

1. 先审计真实仓库、已批准需求、组件、主题、API、权限和测试，再按 `$yulvxing-frontend` 的 S / M / L 分级读取 `docs/frontend/README.md` 指向的相关章节；不要无差别读全仓库。S 局部文案 / 样式修复允许直接做最小安全改动与验证；涉及审核、金额、原件、AI、权限、敏感资料或导出不得按 S 简化。
2. M 任务编码前提交简短页面 / 交互摘要、至少两个布局候选的一句话取舍、适用状态与恢复方式；L 任务执行 Skill 的 P0～P6，先产出任务流、布局决策、交互事件合同和验收矩阵。使用 `06-PAGE-ARCHETYPES.md`、`07-INTERACTION-CONTRACTS.md`、`08-DESIGN-DECISION-PROTOCOL.md`，不机械套“表格 + 弹窗”。
3. 按 `01-DESIGN-SYSTEM.md` 和 `03-FRONTEND-ENGINEERING.md` 复用语义化 Design Tokens、统一布局 / 字阶 / 间距 / 边框 / 状态；不随意新增孤立颜色、字体体系、第三方 UI 套件或全局覆盖，不重建平行组件库。
4. 按 `02-UX-INTERACTION.md` 和 `07-INTERACTION-CONTRACTS.md` 实现事件与状态闭环：触发、前置条件、权限、处理中、成功、失败、恢复、取消 / 撤销与审计；涵盖适用的部分成功、超时、无权限、409 冲突和来源过期。保存失败保留编辑；“保存并下一条”必须等服务端确认后再切换，不能只有空壳按钮。
5. AI 生成内容必须区分“建议 / 待核 / 人工确认”，重要事实、金额、日期、证据出处可跳回有效原件及版本；无来源不得假装已核实。重新生成不得覆盖人工已确认内容或审校留痕。未经授权不得向外部模型上传敏感材料，仍须遵守既有服务端准出门禁。
6. 交付前执行仓库实际存在且与范围相称的 lint、类型、构建、受影响测试、视觉 / 键盘核验；依据 `04-QUALITY-GATES.md`、`09-ACCEPTANCE-ORACLES.md`、`10-VISUAL-REGRESSION.md` 留存真实证据。M / L 的显著页面检查三个桌面视口；L 的重要工作台运行一个完整主路径和两个失败脚本。工具不可用时明确阻断及未验证项，不得伪造截图、进度、统计或测试结果。
7. 结果统一用 `PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE`，未运行必须注明“未验证”；P0 或未获明确豁免的关键 P1 问题阻断宣称验收完成。按 `05-AUDIT-CHECKLIST.md` / `templates/UX-REVIEW-REPORT.md` 交付设计选择、变更文件、命令、截图、风险和回滚方法。修改规范自身时执行 `python scripts/validate_package.py`；静态验证不等于 Skill 行为、UI 或业务测试通过。

## 交互和视觉不可妥协项

- 同一业务语义必须使用一致术语、状态和颜色；颜色不得作为唯一信息载体。
- 工作台有明确层级，优先单一主 CTA；表格/过滤/分页/批量操作/侧栏抽屉遵循统一规则；默认不以层层弹窗承载复杂流程。
- 案件、文件、来源、审核与导出有版本和状态提示；材料失败/部分解析不能伪装成成功；已终核内容变更应提示复核失效。
- 显著操作（删除、覆盖、重新生成、终核、敏感材料外发）必须解释影响范围，确保权限和二次确认符合既有业务规范。
- 前端至少验证桌面主要视口的布局；键盘操作、可见焦点、文字对比度等以 WCAG 2.2 AA 为目标。
- 不为了追求视觉效果加入过度渐变、无意义大卡片、装饰性数据图、动画、伪指标或无法复核的 AI 结论。

## 适用 Skill

- 新建页面、重构交互、设计组件、页面视觉审查、复杂前端功能时，使用仓库 V2.0 Skill：`$yulvxing-frontend`（原位 `.agents/skills/yulvxing-frontend/SKILL.md`，名称不变）。S / M / L 与 P0～P6 的细则由该 Skill 和规范索引维护，不另保留 V1 工作流。
- 小型样式或文案修复按 S 级最小流程；M / L 按需采用设计决策、交互合同和验收模板，S 不要求机械创建长文档。纯后端任务不触发前端流程。

## Code Review Rules

- 标记未经设计的孤立颜色/间距/表单/弹窗、重复组件、没有状态反馈的异步操作、缺少来源/版本的法律材料展示、会覆盖人工确认的 AI 重生成。
- 标记跨案件/角色数据泄露、缺失权限检查、日志或截图泄露敏感信息、未经授权的模型外发；前端隐藏按钮不能替代服务端权限。
- 标记缺少可复现测试证据的“已全部完成”声明。

## 本仓库的技术栈与主题裁决

- 用户端沿用 Vue 3 + TypeScript + Vite + Element Plus / Element Plus X + Pinia + Vue Router + UnoCSS / SCSS；管理端沿用 Vben + Vue 3 + TypeScript + Ant Design Vue + Tailwind CSS。设计参考体系不构成安装另一套 UI 库的授权。
- 用户端现有主色为金色 `#F7B51C`，主题入口为 `ruoyi-web/src/config/design.ts`、`src/styles/brand.scss` 和 `src/styles/var.scss`；规范蓝色及 6px 控件圆角是候选值，不直接替换现有品牌、12px 控件圆角或管理端主题。
- 优先复用现有组件和语义变量。后续若引入 `--yl-*`，须通过现有主题建立语义映射并验证受影响页面；`examples/design-tokens.sample.css` 保持示例用途，不直接导入应用。
- 用户端使用 Node.js >=22.13.0 / pnpm 11.0.9；管理端声明 Node.js >=20.10.0 / pnpm 10.14.0。沿用各自 manifest、工作区和 pnpm 锁文件，不在根目录另起依赖体系。
- 材料上传、解析、AI 建议、人工复核与导出是独立状态；UI 不可把解析成功当作已终核。无有效来源不得假装核实，敏感材料外发须满足既有服务端准出门禁，案件不可用的错误展示须保留既有防枚举边界。
- 新功能使用 `templates/NEW-FEATURE-BRIEF.md`；M / L 按需使用 `templates/DESIGN-DECISION.md`、`INTERACTION-CONTRACT.md` 和 `UX-REVIEW-REPORT.md`。显著改动仍按 `docs/frontend/05-AUDIT-CHECKLIST.md` 留下验收记录，未运行必须写明“未验证”。
- V1 首次接入历史审计保留在 `docs/frontend/INSTALLATION-AUDIT.md`；当前 V2 升级、冲突裁决、备份与验证状态见 `docs/frontend/V2-UPGRADE-REPORT.md`。规范文件不等于已接入自动阻断；以后所有新增或修改的前端模块统一按 V2.0 执行适用的 UI、UX、布局、状态、工程和验收规范，本次升级不授权新业务开发或全站重构。
